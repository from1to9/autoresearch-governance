# Launch and Lifecycle

Choose the smallest mode that preserves ownership and necessary independence.

| Work shape | Mode |
| --- | --- |
| One answer, diagnosis or bounded change | Ordinary task |
| One durable outcome with a coherent owner | One autonomous task |
| Independent directions, contested claims or separately owned resources | Hierarchical campaign |

A role diagram grants no permission to create chats, subagents, recurring tasks or
external actions. Apply current human authority and harness requirements. Reuse a
suitable existing task. Use [harness adaptation](harness-adaptation.md) only when
capabilities are missing or unmapped; optional automation is not a launch gate.

## Campaign and roles

Record the outcome, acceptance boundary, hard constraints, non-goals, causal
questions, resource/mutable-state ownership, relevant retry/review rules and return
path in the existing task record. The [campaign template](../templates/campaign.yaml)
is a starting aid; ordinary tasks need no campaign paperwork.

The sponsor defines outcomes and authority. G0 owns the human gateway and manager
repair; G1 owns decisions, dependencies and acceptance; G2 owns one coherent
execution or review task. Roles needing independence receive separate contexts.
Other responsibilities do not require a new chat merely for a complete diagram.

Use the relevant [supervisor](../prompts/supervisor.md),
[manager](../prompts/manager.md), [researcher](../prompts/researcher.md) or
[reviewer](../prompts/reviewer.md) prompt with its lease/checkpoint and essential
references. Do not paste the manual or parent history into each role. Bound
concurrency by authorized ready questions, resources and supervision capacity;
there is no universal agent count.

Use [model routing](model-routing.md) for judgment versus sealed mechanical work.
Give a [lightweight worker](../prompts/lightweight-worker.md) explicit inputs,
verifier and escalation conditions. Professional lenses matter only when they
produce distinct evidence, mechanisms or tests.

## First evidence

Before convergence, cover the leading, orthogonal and falsification/boundary
routes, or record why the authorized scope/resources require a narrower search
and when alternatives reopen. Freeze independent first passes before discussion.

Review the implementation diff before costly validation. Consolidate the checks
that could invalidate the first outcome, resolve concrete findings and run the
smallest complete path. Do not add serial reviewers or speculative defensive work
while postponing real evidence. Ask only for missing external decisions; resolve
ordinary reversible choices within the lease.

A complete experiment applies the intended intervention to authoritative inputs
and reaches analyzable outcomes. It is complete in causal/execution path, not
maximum scale. Use the actual result to repair, keep, revert, pivot or scale.
Tests and review support this loop; they do not replace it.

## Delivery and continuity

Executors own checks, recovery, observation and delivery. They directly request
required authorized review and resolve findings with the reviewer before notifying
management. A received handoff ends the management turn; follow the
[management stopping rule](communication-liveness.md#4-handoff-completion-and-the-management-stopping-rule).

Keep a next owner/action/wake for unfinished work. Reuse a coherent task, queue it
with a reopening condition when dependencies are unavailable, or retire the exact
route with evidence and a future reopening condition. Rotation needs a concrete
independence/isolation/recovery reason and an authorized successor; do not create
a replacement merely because a turn ended.

Management resumes on final delivery, a decision blocker or an explicit user
query/intervention. An authorized monitor follows its existing cadence and event
conditions; it does not authorize a second observer. Use
[communication and liveness](communication-liveness.md) for an actual missing
owner or overdue delivery, not routine reassurance.

## Finish

Match the requested outcome to sufficient evidence and required independent
review. Keep source, delivery, deployment, runtime adoption, recovery, performance
and domain acceptance distinct. State limitations and remaining owners. Apply only
authorized cleanup and monitor disposition; preserve valid inputs and evidence.

If execution exposes a reusable governance defect, repair its canonical rule
through [evolution](evolution.md) while compatible work continues. Finish that
repair once its requested behavior and sufficient checks pass.
